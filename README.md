# 研英批改

研英批改是一款面向单一用户的 Android 主观题练习与 AI 批改工具。它把考研英语主观题、图片识别、结构化评分和复习指导放在一个本地优先的工作流中，并采用简洁的 iOS/Cupertino 风格界面。

## 功能

- 内置 2002—2026 年考研英语主观题：翻译、小作文和大作文。
- 翻译题显示完整文章，并明确标出五个待译句；2002—2004 年按旧题型记录。
- 手动输入答案，或从相机/系统图片选择器导入最多六张图片。
- 图片可排序、旋转、裁剪和删除；原图保留在应用沙箱，识别时使用压缩副本。
- OCR 可在百度手写 OCR 与支持图片输入的视觉 LLM 之间明确选择。
- 评分分为严格评分与复习指导两个阶段，分别显示状态、支持取消和单独重试。
- 提示词和 AI 提供商是两个独立的设置界面；应用内的提示词均可编辑、预览、单项恢复或全部恢复。
- 支持 OpenAI Responses、OpenAI-compatible Chat Completions、Anthropic Messages 和 Gemini `generateContent` 协议，并允许自定义网关。
- 历史记录保留答案、题目、提示词、模型和每次评分版本的快照。
- 手动导出/恢复完整明文备份，导出前会明确提示其中包含 API 密钥和图片。

本项目不包含韦氏词典、生词查询、账号系统、服务器端代理、云同步或离线 AI。

## 界面与使用流程

底部导航包含“练习”“历史”“设置”三个入口。设置中的“提示词”和“AI 提供商”分别进入独立的全屏编辑界面，不把两类配置混在同一表单中。

一次练习的基本流程是：选择年份和题型 → 阅读题文 → 手动输入或导入图片 → 选择 OCR/视觉模型并确认识别稿 → 运行严格评分 → 查看复习指导。修改答案、提示词或模型后重新评分会生成新的版本，旧版本不会被覆盖。

## AI 提供商配置

应用采用 BYOK（Bring Your Own Key）模式，密钥只保存在本机应用沙箱中，不上传到本项目的服务器。每个提供商配置包含名称、协议、HTTPS Base URL、密钥、额外请求头、模型 ID、视觉能力和启用状态；模型选择、连接测试和错误信息都在“AI 提供商”界面完成。

识别、翻译评分/指导、小作文评分/指导、大作文评分/指导分别绑定提供商和模型。每次练习可临时覆盖绑定，但不会修改全局配置。应用不会自动重试、静默切换模型或在失败时改用另一家提供商。

## 本地数据与备份

练习、图片、提示词、提供商、阶段绑定和评分原始响应都写入应用私有目录。项目不额外启用 Keystore、数据库加密或应用锁；因此使用设备系统锁保护设备本身很重要。

备份是用户主动触发的明文 ZIP，包含 API 密钥和图片。导出页面会显示不可跳过的泄露警告。恢复前会校验清单和哈希，确认后以原子方式替换现有数据；损坏或失败不会删除原数据。

## 开发与验证

项目使用 Kotlin、Jetpack Compose 和 Android Gradle Plugin。最低支持 Android 12，应用仅面向竖屏手机。提交前应运行仓库中的 GitHub Actions；Actions 会在 GitHub runner 上执行单元测试、静态检查、Compose 测试和 debug 构建。

本地开发需要 Android SDK、JDK 17 和可用的 Android Gradle 环境。由于发布流程在 GitHub Actions 完成，仓库维护者不应把密钥、签名文件、`local.properties`、导出备份或原始资料压缩包加入版本控制。

## 发布

推送形如 `v0.0.1` 的标签会触发 release workflow。workflow 从 Actions Secrets 读取以下四项：

- `ANDROID_KEYSTORE_BASE64`
- `ANDROID_KEY_ALIAS`
- `ANDROID_STORE_PASSWORD`
- `ANDROID_KEY_PASSWORD`

它会在 runner 临时目录解码签名仓库，运行测试和 release 构建，使用 `apksigner verify` 校验签名，生成 SHA-256，并将重命名后的 APK 与校验文件发布到 GitHub Releases。签名仓库不会写入仓库或作为 artifact 上传。
